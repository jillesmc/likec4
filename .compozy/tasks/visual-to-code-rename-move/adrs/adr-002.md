# ADR-002: Snapshots rewritten server-side and kept in the undo history

## Status

Proposed (amends phase-1 ADR-004, which kept snapshot writes on the client after sync)

## Date

2026-10-20

## Context

Manual-layout snapshots identify nodes by FQN (`id`, `parent`, `children`, `modelRef`) and edges by
source and target. Unnamed views (`view of x`) have ids hashed from `x`. After a rename or move,
every snapshot that shows an affected element would report the node as removed and a new one as
added, and an unnamed view's snapshot would be orphaned. A rename touches views other than the
open one, so the phase-1 client-side `save-view-snapshot` cannot keep them in sync, and canvas
undo must restore them with the `.c4` files.

## Decision

- A pure core function `renameFqnsInSnapshot(view, fqnMap)` maps every id-like field of a snapshot
  through the FQN map (exact match or `old.` prefix). Edge ids are left as is (drift matching
  falls back to source and target).
- After a successful apply, `ModelChanges` rewrites, through `LikeC4ManualLayouts`, every snapshot of
  the affected projects that contains a mapped id, and moves snapshots of views whose id changed.
- The history entry stores each touched snapshot's `before` and `after`. Undo writes the `before`s
  (deleting files that did not exist), redo the `after`s. The `stale-undo` check covers the `.c4`
  files as in phase 1.

## Alternatives Considered

### Alternative 1: Client-side rewrite after sync

- **Cons**: only the open view is known to the client.
- **Why rejected**: leaves the other views drifted.

### Alternative 2: Snapshot edits inside the `WorkspaceEdit`

- **Description**: send snapshot JSON changes as text edits / file renames in the same edit.
- **Pros**: VSCode's own undo would cover them.
- **Cons**: snapshots are written by `LikeC4ManualLayouts` through the file system in phase 1; in
  the dev server there is no `WorkspaceEdit`; JSON text diffs of large snapshots.
- **Why rejected**: two write paths for the same files.

## Consequences

### Positive

- Renames keep every manual layout intact; one Ctrl+Z restores everything.

### Negative

- History entries grow by the snapshots' size (bounded by the phase-1 history size cap).

### Risks

- A snapshot edited by hand between the gesture and the undo is overwritten by the undo; accepted
  (snapshots are tool-owned files).
