# ADR-003: Text F2 shares the planner but not the guard or snapshots

## Status

Proposed

## Date

2026-10-20

## Context

The owner wants F2 in the `.c4` editor too (Q3). In LSP, `textDocument/rename` returns a
`WorkspaceEdit` that the editor applies itself, with its own undo. The server never learns whether
or when it was applied, so it cannot run the post-apply guard, revert, or record a history entry.

## Decision

`LikeC4RenameProvider` is re-enabled and delegates to the planner of ADR-001 for elements,
deployment nodes and instances (`prepareRename` refuses everything else). It returns only the
`.c4` edits. It runs the preconditions that need no apply (valid name, no sibling collision) and
returns their message as an error. Snapshots are not rewritten: views with a manual layout report
drift as today, and the user can fix them from the canvas.

## Alternatives Considered

### Alternative 1: Route F2 through `change-view`

- **Description**: a client command that calls the canvas op instead of LSP rename.
- **Cons**: VSCode-specific; other LSP editors would not get it; bypasses the editor's undo.
- **Why rejected**: the owner asked for the editor's F2.

### Alternative 2: Simulate the apply in memory to guard

- **Cons**: needs a second workspace build per rename; complex.
- **Why rejected**: diagnostics already show a broken result, and editor undo fixes it.

## Consequences

### Positive

- Every LSP client (VSCode, others) gets a correct rename.

### Negative

- F2 in the text can, rarely, produce a capture the canvas would refuse; it shows as diagnostics
  only when it causes an error.
