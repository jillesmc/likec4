# ADR-001: Reference rewrite from the language server's index, with a resolution guard

## Status

Proposed

## Date

2026-10-20

## Context

A rename or move must rewrite every reference to the affected elements. LikeC4 references are
chains of segments (`FqnRef`, `StrictFqnRef`, `StrictFqnElementRef`, `Imported`), and each segment
is resolved by `LikeC4ScopeProvider` with several shortcuts: sibling and ancestor short names,
unique descendants (`cloud.db` for `cloud.backend.db`), `this` / `it`, imported names, unnamed
instances named after their element. The same text can therefore point to different elements in
different places, and a new name can silently capture a short name that used to resolve
elsewhere, without any linking error.

## Decision

- The planner lists references with Langium's `References.findReferences` on the affected AST
  nodes (the element, its descendants for a move, unnamed instances of a renamed element, and
  `Imported` nodes importing it). Each reference segment whose text equals the old name is
  replaced (rename). For a move, whole chains are replaced with the full new FQN (`_spec.md`
  rule 6).
- Before applying, `ModelChanges` records the multiset of `(document, resolved target FQN)` pairs of
  every cross-reference in the affected projects. After applying and rebuilding, it records it
  again and compares it with the baseline mapped through the plan's FQN map. Any difference, or any
  new error, reverts the change and refuses it with `invalid-result`, naming the first reference
  that differs.

Refined during implementation (2026-10-21): only whole references are counted (the item `a.b.c`
points to; inner segments are the path, which a move rewrites), documents are not part of the key
(a move takes references to another file), and the check is that every reference that existed still
points to its item: a change may add references, such as the `include` of a move.

## Alternatives Considered

### Alternative 1: Text search for the old FQN

- **Description**: regex over `.c4` files for `old.fqn` and its suffixes.
- **Pros**: simple, no dependency on the index.
- **Cons**: cannot tell short names, unique-descendant shortcuts and `this`/`it` apart; renames
  unrelated identifiers that share a name.
- **Why rejected**: wrong results on ordinary models.

### Alternative 2: Langium's `DefaultRenameProvider` as is

- **Description**: re-enable the default provider.
- **Pros**: no new code.
- **Cons**: rewrites `this`/`it` and imported aliases' text, knows nothing about unnamed instances,
  moves or snapshots, and cannot refuse a capture.
- **Why rejected**: this is why the provider was disabled.

### Alternative 3: Errors-only guard (phase-1 rule 11)

- **Cons**: a capture produces no error, only a different target.
- **Why rejected**: misses the most dangerous failure.

## Consequences

### Positive

- One planner serves the canvas ops and the text rename.
- Every accepted gesture keeps all references pointing to the same elements.

### Negative

- Two walks over all references of the affected projects per gesture.

### Risks

- A reference kind not recorded by the index is not rewritten; the guard then refuses the gesture
  instead of breaking the model.
