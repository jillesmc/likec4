# ADR-001: New relations are written inside the source element's block

## Status

Proposed (resolves epic Q1; needs owner confirmation)

## Date

2026-10-12

## Context

`add-relation` (slice 1) needs a deterministic place to write `A -> B`. The DSL allows a relation
nested in the source's body (`-> B`, implicit source), at `model {}` level in any file
(`A -> B`), or inside an `extend A { }`. D4 already places new *elements* inside their parent's
block in the parent's file.

## Decision

Write the relation as `-> <target>` as the last child of the source element's **definition** block,
in the file holding that definition (adding `{ }` if the element has no body). If the source is
not editable from this workspace (defined in another project or imported), write
`<source> -> <target>` in the first `model {}` of the file defining the current view.

## Alternatives Considered

### Alternative 1: `model {}` level of the source's file

- **Description**: `A -> B` at top level of the source's file.
- **Pros**: no body manipulation; simple anchor (end of `model {}`).
- **Cons**: relations drift away from their element, and large files collect an unordered tail of
  relations.
- **Why rejected**: inconsistent with D4 and with how hand-written models in this fork are laid
  out.

### Alternative 2: `model {}` of the view's file

- **Description**: everything created in a view goes to that view's file.
- **Pros**: one file per gesture, so atomicity is trivial.
- **Cons**: scatters a model's relations across view files, making them hard to find.
- **Why rejected**: kept only as the fallback for non-editable sources.

## Consequences

### Positive

- Mirrors D4; the relation sits next to its source.
- Reuses the same CST anchor code as add-element.

### Negative

- Model edit and auto-include can land in different files, so a multi-file `WorkspaceEdit` is
  needed from slice 1.

### Risks

- Elements defined as `extend` only in some files: the definition file must be located through
  `ModelLocator.locateElement`, not the first AST hit (UT-010, US-002.EC-8).
