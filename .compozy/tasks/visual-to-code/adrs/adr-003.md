# ADR-003: Dev-server model undo is a server-side inverse-edit stack joined to canvas history

## Status

Accepted (implements D13). Amended by ADR-004: the history also applies in VSCode.

## Date

2026-10-12

## Context

D13: undo/redo of model edits in `likec4 start`; VSCode uses native undo. The canvas *already*
binds Ctrl+Z / Ctrl+Shift+Z (`editor/actor/hotkey.ts`) to an in-actor **layout** history of
snapshots (`actions.ts` undo/redo). In the VSCode preview the webview has focus, so VSCode's
native undo is not reachable from the canvas.

## Decision

- `LikeC4ModelChanges` keeps, when no LSP connection exists, an in-memory per-project stack of
  `{ uri, afterHash, inverse: TextEdit[] }` (cap 100) plus a redo stack. It is exposed as the LSP
  requests `likec4/undo-change` / `likec4/redo-change` and the vite RPC `undoChange` / `redoChange`.
- `LikeC4EditorCallbacks` gains optional `undoModelChange` / `redoModelChange`. The SPA wires them;
  VSCode preview does not.
- The editor actor's existing history gets a second entry kind, `model`. It is pushed when a model
  op succeeds *and* the port has `undoModelChange`. Ctrl+Z pops the latest entry: `layout` →
  existing behaviour; `model` → `port.undoModelChange`. Redo is symmetric.
- In VSCode, model edits never enter the canvas history. They are undone in the `.c4` editor.

## Alternatives Considered

### Alternative 1: Client-side stack of inverse ops

- **Description**: the actor stores inverse `ViewChange`s (e.g. add → delete).
- **Pros**: no new RPC.
- **Cons**: inverses of retitle/exclude/delete are not expressible as ops without new "restore
  text" ops; and the client has no file text.
- **Why rejected**: the server already has the exact edits.

### Alternative 2: Separate hotkeys for model undo

- **Description**: e.g. Alt+Z for model, Ctrl+Z for layout.
- **Pros**: no history merging.
- **Cons**: surprising, and two mental models.
- **Why rejected**: users expect one history (US-006 AC-3).

## Consequences

### Positive

- One Ctrl+Z history on the canvas in the dev server.
- Undo is exact (inverse text edits), and refuses safely when the file changed (`stale-undo`).

### Negative

- The stack is lost on dev-server restart.
- VSCode has asymmetric behaviour (canvas Ctrl+Z = layout only), which is documented in US-006.EC-4.

### Risks

- Interleaving with layout snapshots written by D12: undo order is model → snapshot (two Ctrl+Z
  to fully revert an add-element in a manual view). This is accepted and covered by E2E-004.

## Implementation Notes

The inverse edits are computed by diffing the pre/post text of each touched document over the
edited ranges, and are stored after the guard passes.
