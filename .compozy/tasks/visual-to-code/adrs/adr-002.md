# ADR-002: Precondition re-validation instead of document-version tokens

## Status

Proposed (replaces the epic's §4 "each op carries the document version")

## Date

2026-10-12

## Context

The epic asked for optimistic concurrency: "each op carries the document `version` it was computed
against". However, the canvas lives in `packages/diagram`, which by repository rule knows nothing
about documents or URIs. It only has a `LikeC4Model` and `viewId`s. A single gesture can also touch
two files (ADR-001), and in VSCode, document versions change on every keystroke in unrelated parts
of the file, so a version token would reject harmless gestures.

## Decision

Do not add a version to `ViewChange`. At apply time, `LikeC4ModelChanges` re-validates every
precondition against the current workspace: endpoints/parent/target exist, no identifier
collision, kind exists, target editable, delete has no references. Requests are serialised per
project. Any failed precondition rejects the gesture with a specific code. The post-apply guard
(Business Rule 11) catches the remaining invalid outcomes.

## Alternatives Considered

### Alternative 1: Document version per touched URI

- **Description**: the host attaches `{uri, version}` to each op.
- **Pros**: detects any concurrent edit.
- **Cons**: leaks document identity into the diagram contract, and causes false rejections on
  unrelated edits.
- **Why rejected**: it violates layering, and the user-visible benefit is nil (the meaningful
  conflicts are exactly the precondition failures).

### Alternative 2: Model hash per project

- **Description**: hash `ParsedLikeC4ModelData`, and reject on mismatch.
- **Pros**: layering-clean.
- **Cons**: rejects on any model change, including unrelated ones; hashing cost per gesture.
- **Why rejected**: too coarse.

## Consequences

### Positive

- No contract change for hosts; the ops stay intent-only.
- Only real conflicts are rejected.

### Negative

- A gesture made on a slightly stale canvas may succeed against a newer model (e.g. the target was
  retitled meanwhile). This is acceptable because the intent (connect A to B) is still valid.

### Risks

- A missed precondition gives an unexpected write; the post-apply guard and IT-004 bound the damage.
